# Smartician: project status

Last updated: 2026-11-06. This file describes what exists in the repository and what has been verified live. Where something is built but not proven, it says so.

## 1. What this project is

A mixed-reality trainer for a CNC vertical machining center, running on a Meta Quest 3.

- A worker stands in front of a virtual copy of the machine and follows (Learn mode) or performs unaided (Test mode) a 22-step start-up, set-up and run procedure.
- An **AI technician on 0G** is the only judge. It watches the machine state and the worker's actions, corrects mistakes by voice and text, and decides at four checkpoints whether the worker may continue.
- Every session becomes a hash-chained **episode log stored on 0G Storage**, with its root hash **anchored on 0G Chain**.
- A worker who passes Test mode gets an expiring, revocable **ENS certificate** (a subname of `smartician.eth` on Sepolia). Its records point back to the 0G evidence.
- **World ID Agent Pass** proves that the person taking the Test is a real human, through a phone check-in before they put the headset on (section 7).

## 4. The Unity app

**Stack:** Unity 6000.3.28f1, URP, Meta XR SDK 207.0.1 on OpenXR (the Meta XR Feature must be enabled in the OpenXR settings), Quest 3 passthrough, controllers only, glTFast, Newtonsoft, TextMeshPro. Cleartext HTTP is no longer needed because the backend is on HTTPS.

**Build:** the scene is generated by `Tools > MR Trainer > Build Scene` (editor scripts in `UnityProject/Assets/Editor`). The backend address is the constant in `Scripts/Core/Config.cs`.

**What the worker experiences**
1. Welcome screen showing the machine's ENS passport (read live) and the Learn and Test buttons.
2. The machine spawns about 2 m in front of the worker, on the floor, so nobody has to walk around.
3. Every control is interactable by ray (isolator, E-STOP, power, mode selector, home buttons, tool, door, workpiece, clamp, program, feed, coolant, cycle start and stop). The machine enforces real interlocks locally (door open blocks cycle start, and so on).
4. **Learn mode** highlights each control and explains why, with up to three hints counted. **Test mode** removes the highlights.
5. After every action the app sends the new actions and machine state to the backend. The 0G judge answers within about 2 to 3 seconds. A mistake produces a short spoken and written correction. Refused actions (for example a blocked power button) are sent too.
6. At four checkpoints the judge must pass the worker before the next stage unlocks.
7. At the end the app saves the record (storage plus chain anchor). After a Test pass it issues the ENS certificate (named from the phone check-in), checks it live, and shows a **View certificate** button.

**Test mode needs a check-in:** when World is configured on the server, tapping Test asks whether a verified worker is waiting. If not, the headset says "Check in first" with the page address. If one is, it asks "Start as <name>?" and binds that person to the session.

**Safety behaviour:** if the backend or 0G cannot be reached, a red "Do not continue" panel appears and nothing unlocks. There is a Retry button. There is no offline stub and no local rule checker that can override 0G.

**Panels:** step card (carry or pin it with the left grip, `X` to resume following), toasts, modal, coach banner with a "0G ONLINE" chip, and the certificate panel.

**Procedure (3 stages, 22 steps, 4 checkpoints, hint limit 3)**
1. Power-up and home: isolator on, release E-STOP, power on, HOME mode, home Z, home X and Y (**checkpoint**).
2. Set-up: select tool T1, open door, place workpiece, clamp it, close door (**checkpoint**).
3. Run: program O1001, DRY mode, feed 50, dry cycle (**checkpoint**), AUTO mode, feed 100, coolant on, production cycle (**checkpoint**), open door, remove part, power off.

**Reliability work (done this week)**
- The office network blocked QUIC and stalled new connections from the Mac to 0G, so the backend moved to Railway.
- 0G calls use short per-attempt timeouts with fresh-connection retries (up to 6 attempts, 27 s overall) and a keep-alive request every 4 s.
- Answers were being cut off at 200 tokens, which produced "reconnecting" popups. The limit is now 450 and a missing closing brace is repaired. Result on the hosted server: **0 safe-stops in 32 consecutive calls**, median 2.7 s, slowest 7.8 s.

**Episode record contents:** every action, every judge verdict (with 0G request id and latency), every voice line, hash-chained. The newest verified example is session `d68027d0-...`: 29 records, 26 judge observations, outcome `test_pass`, root `0x5be0b15b1f59d64d82a9b38a7098917046d04a8f389619f8e4263c8623640caf`.

**Not built:** speech-to-text so a worker can ask the technician a question out loud (the model `whisper-large-v3` is available on the router).

## 6. ENS integration (Sepolia, ENSv2)

**Names**
- Parent: `smartician.eth`.
- Machine passport: `cnc-01.smartician.eth`, with records for model, the procedure's 0G root hash and guide version. Read live at the welcome screen.
- Guide identity: `guide-cnc.smartician.eth`.
- Certificates: `<name>-cert.smartician.eth` (a number is added if the name is taken; `cert-<id>` if no name is given).

**Contracts** (addresses in `backend/deployments/sepolia.json`): a resolver, a subname registry (UserRegistry), and `CertificateRegistrar`, which lets only the issuer wallet issue (up to 365 days) and revoke.

**Certificate records:** `mrt.evidence` (`0g://` plus the 0G root hash), `mrt.verdict`, `mrt.issuedAt`, then `alias`, `class` (`Certificate`) and `description`. These are the key-value pairs stored on the name. The issuer wallet can write only its own keys; others are refused.

**Live checks:** `GET /credential/<label>` reads ENS at that moment. A revoked or expired certificate returns `valid: false`.

**Verified examples**
- `da-cert.smartician.eth`: valid until 2027-02-04, `alias = Da`, `class = Certificate`, evidence matches the 0G anchor above.
- `cert-9e8acec7.smartician.eth`: older certificate (no alias), evidence `0x93fea225...2ce35`, also matches an anchor.
- `npm run proof` rebuilds this whole proof sheet (0G anchors, a Storage download with hash-chain verification, ENS certificates and their record transactions) from the chains.

**Decided not to do yet:** the ENSIP-27 `schema` record (a link to a JSON file describing the fields) and ENS token metadata (NFT JSON per name). Both are small additions if the ENS team asks for them.

**Not done:** the APPROVER wallet and the `mrt.approval` record (reserved for the World step).

## 7. World ID Agent Pass

**What it proves:** the person taking the Test is a real human who completed a fresh World verification. It does not prove who they are. The name is a label the worker types, and the page says so. Hackathon proofs use test identities, so the product never claims production-grade verification.

**Flow (built)**
1. The worker opens `https://eth2026.dakshkulkarni.in/checkin` on their phone (a QR at the station can point there) and taps **Verify with World**.
2. The backend starts a World device-authorization request. The page shows a button that opens World's approval page, plus a code and a QR for laptops, and waits.
3. The worker approves. The backend polls World, then validates the signed ID token itself: RS256 signature through World's keys, issuer, audience, expiry, `auth_time` no older than this attempt, and `amr` present. The browser result is never trusted.
4. The page shows "Verified", then an optional **Name your licence** field with a live preview such as `daksh-cert.smartician.eth`. A hash of the World ID is kept, never the raw ID.
5. On the headset, tapping **Test mode** finds the waiting check-in and asks "Start as <name>?". The session claims it, and the proof of human is written into the episode log that goes to 0G Storage.
6. After a Test pass, the certificate is issued from that same check-in (single use), named from the check-in, with an `mrt.human` record on the ENS name.

**Unsuccessful paths (all leave Test locked and issue no licence):** denied, expired, cancelled, a forged or stale token, World unreachable, or a headset with no check-in waiting. Without a verified check-in the certificate route returns 403.

**Verified so far:** `npm run smoke:world` runs the whole backend against a local stand-in World server, including the HTTP routes. It covers approve, slow_down, deny, forged token, stale token, cancel, expiry, claiming, retry, single use, and confirms the device code, subject and full hash never leave the server. The check-in page was checked in a phone-sized browser. It has **not** run against the real World service or on the headset.

**Setup still needed from the project owner**
1. In `auth.world.org/portal`, create an app. Redirect URI `https://eth2026.dakshkulkarni.in/world/callback` (required but unused by the device flow), authentication method client secret basic, accepted accounts "Any account".
2. Set `WORLD_ISSUER=https://auth.world.org`, `WORLD_CLIENT_ID` and `WORLD_CLIENT_SECRET` in `backend/.env` and on Railway. With these unset, Test mode is not gated and everything behaves as before.
3. Run `npm run ens:grant-profile` once more so the issuer may write `mrt.human`.
4. Deploy with `railway up`.

**Design notes**
- A verified check-in stays usable for 30 minutes, or until a certificate is issued from it. A failed Test can be retried without checking in again.
- If two people check in, the headset takes the oldest and the worker confirms it. "Not me" releases it.
- "One human, one licence" is recorded, not enforced: the hash is on the licence and in the evidence, and the same human could hold more than one licence. Enforcing it would risk blocking repeat demo runs with the same test identity.
- The check-in store is in memory, like sessions. A redeploy clears it.

## 8. Hosting and deployment

- **Backend:** Railway (project `ample-endurance`, service `Eth2026`), built from the root `Dockerfile`, region US East. Railway's trial credit is small, so pause the service after the event.
- **Address:** `https://eth2026.dakshkulkarni.in` (a DNS-only CNAME to the Railway domain, with a `_railway-verify` TXT record, in Cloudflare; the domain is registered at Hostinger and its DNS lives at Cloudflare).
- **Deploying:** pushes to GitHub did **not** trigger Railway builds reliably. Deploy from the repo root with `railway up` after `railway login` and `railway link`.
- **Sessions are in memory:** a restart or redeploy during a training session loses it.
- **Variables to set on Railway** (names only, never commit values): `ZG_API_KEY`, `ZG_REGISTRY_ADDRESS`, `AGENT_PRIVATE_KEY`, `OWNER_PRIVATE_KEY`, `ADMIN_TOKEN`, and later `WORLD_ISSUER`, `WORLD_CLIENT_ID`, `WORLD_CLIENT_SECRET`, `APPROVER_PRIVATE_KEY`.
- The old Cloudflare tunnel setup is obsolete. Do not use a tunnel from the office network.

## 9. Backend API

| Endpoint | Purpose |
|---|---|
| `GET /health` | Status, model, registry address, wallet and World configuration |
| `POST /session/start` | Starts a session |
| `POST /session/:id/observe` | Sends new actions, machine state and (for checkpoints) a frame; returns the 0G verdict |

| `POST /session/:id/finalize` | Uploads the episode to 0G Storage and anchors it on 0G Chain |
| `POST /session/:id/certificate` | Issues the ENS certificate after a finalized `test_pass`; needs a claimed verified check-in when World is configured |

| `GET /worker/ready`, `POST /session/:id/claim` | The headset finds a verified worker and binds them to a session |

## 11. Keys and safety rules

- Use throwaway testnet wallets with no real funds. Keys live in `backend/.env` and Railway variables only; they are never committed or pasted into chat.
- Roles: OWNER (deploys and grants), AGENT (the backend's issuer: issues and revokes certificates, anchors on 0G, pays storage fees), APPROVER (reserved for the World sign-off record, not set yet).
- Private planning notes are kept outside the repository.
- 0G must be the real decision-maker: no hard-coded verdicts and no offline fallback. If 0G is unreachable, the app stops safely.

## 13. Known issues and lessons

- Unity sometimes fails to register a new script. Delete its `.meta` file, refocus Unity or reimport.
- Unity compile errors can be checked without opening the editor by running Unity's bundled compiler on a copy of its response file; there are no automated Unity tests.
- The certificate panel layout was calculated rather than designed in the editor. It was reported working on the headset, but spacing may still need a pass.
- The hosted backend's activity log is on Railway's disk and is lost on redeploy; use Railway's logs.
- A revoked or expired certificate cannot be un-revoked; issue a new one.

## 15. Demo checklist

1. Welcome screen shows the live ENS passport.
2. Learn mode: do **Home X and Y before Home Z**. The machine allows it, the AI technician flags it by voice, and the 0G request id is shown.
3. Try cycle start with the door open. It is blocked locally; the interlock is separate from the AI.
4. Disconnect the network and make a move. The checkpoint safe-stops and nothing unlocks.
5. Test mode: run all 22 steps without hints. Pass all four checkpoints.
6. Name the certificate, then open **View certificate**. Show the records card and the three proof lines.
7. Run `npm run proof` (or open the links): the same root hash appears on 0G Storage, the 0G Chain anchor and the ENS `mrt.evidence` record.
8. Revoke the certificate with the revoke endpoint and show `/credential/<label>` flip to invalid.
9. World: check in on a phone and Test unlocks; deny once and it stays locked.
